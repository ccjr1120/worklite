  新发现：records 500 的根因

  这个会话在 agent_execution_events 里存了 923 条 snapshot 事件，每条约
  1.1MB，加起来约 1GB。原因是 Codex 每产生一条 activity，都会触发
  publishSnapshotForExecution（agent-executions.service.ts:695），每次都把完整的
  codexTask 写成一条新事件，里面包括全部 operations 和每条 operation 的完整
  result。records 接口会读出全部历史事件，所以超出了字符串长度上限。截断单个字段
  解决不了，而且每跑一次长 Codex 任务，部署库就会多出约 1GB。

  实施方案

  1. 部署时建立托管基线（架构变更）
     - pnpm deploy:local 改成先运行 bump-deployment-version.mjs，再运行 node 
       scripts/upgrade-runner.mjs deploy deployment。删除
       install-local.sh、start-local.mjs 和 start-background.mjs。
     - runner 新增 deploy 命令，按当前状态分两种情况：
       - 还没有 current.json：走现有的 install 流程（快照 → 编译 → 隔离预检 →
         备份 → 启动托管服务）。预检通过后，如果目标端口被旧进程占用，只停
         .data/deployment/worklite-local.pid
         记录的那个进程组，并先确认它是本项目的
         start-local.mjs；其他进程占用端口就拒绝执行。
       - 已经有基线：生成一个由操作人员授权的升级任务，走和 Chat
         重新部署完全相同的 run
         流程（预检、交接、冻结、备份、切换、失败回滚），同步等它结束后再返回。
     - 风险：首次接管时，旧服务停掉后如果托管服务启动失败，会恢复数据并报错，但
       不会重启旧服务。旧服务是从源码 nest start
       起来的，重启它并不等于回到旧版本，所以只能重新执行一次部署。
     - 要同步更新的文档和配置：docs/project-architecture/README.md（部署章节和
       Changelog）、docs/feishu-bot/upgrades.md、AGENTS.md、System Helper
       prompt（packages/db/src/client.ts）、team-resources.service.ts 里的
       capability metadata。Chat 遇到「未托管」时，提示改成运行 pnpm 
       deploy:local。
  2. Codex 结果解析（chat-codex-tasks.service.ts）
     - 严格解析失败后，先把字符串字面量里的原始控制字符转义，再解析一次。
     - 如果还是失败，任务仍标记为 failed，错误写明「结果不是有效
       JSON」，同时把原始输出保存到 result，不再丢失。
  3. Chat 上下文
     - inspect-codex-task.mjs 默认只返回摘要：状态、错误、result、各 phase 的
       activity 计数、最近 20 条 activity，以及不带 result 正文的 operations
       状态列表。新增可选参数 operationKey，用来读取单条 operation 的完整结果。
     - toolCallOutput 对 skill_script 输出设一个上限（暂定 60k
       字符），超出部分截断，注明完整输出仍保留在记录里。
  4. records 与快照膨胀
     - records 接口只返回最新一条 snapshot 事件，其余事件照常返回。
     - 推荐一起修：Codex 进度快照里的 operations 不带 result 正文，每条快照从约
       1MB 降到 KB 级。Web 端需要展示单条 operation
       详情时，改为按需请求。这一项会改动 Web 的 Codex
       面板（transcript.tsx:39），要走 UI 工作流。
  5. 改完后只做类型检查，不构建、不跑测试，也不部署。真正的首次托管部署要你另外
     授权后再执行。

  1. 已有基线时，pnpm deploy:local 走带交接的完整升级流程，可以吗？
  2. 第 4 项里的快照瘦身要不要一起做？它会动到 Web 的 Codex 面板。
  3. 已经存进部署库的约 1GB 历史 snapshot
