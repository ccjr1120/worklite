# 飞书总 Agent 接入

WorkLite 使用受保护的 **Chat** 作为网页与飞书的总 Agent。飞书通过官方 Node SDK 的出站长连接接收消息与卡片回调，无需为事件另开公网 HTTP 回调服务。网页和飞书共用 Agent 配置与服务端分派入口，对话记录各自独立。长连接行为依据[官方 SDK 实现与说明](https://github.com/larksuite/node-sdk/blob/main/docs/channel.zh.md)。

## 应用与权限

可在 WorkLite Chat 的 Channels 页扫码创建个人 Agent 应用，或在[飞书开放平台](https://open.feishu.cn/app)使用已有企业自建应用。启用机器人，把使用者加入应用可用范围。为该应用启用下列应用身份权限，并按企业流程发布：

| 权限 | 用途 |
| --- | --- |
| `im:message.p2p_msg:readonly` | 接收机器人私聊文字 |
| `im:message:send_as_bot` | 发送回复、任务卡片与文件消息 |
| `cardkit:card:write` | 创建卡片实体，流式更新回复及局部更新任务卡片 |
| `im:resource` | 上传回复文件和任务二维码图片 |

权限名称及对应能力可参照[飞书官方接入说明](https://www.feishu.cn/content/article/7602519239445974205)。卡片权限及原生流式能力参照[官方 CardKit 流式说明](https://open.feishu.cn/document/cardkit-v1/streaming-updates-openapi-overview)。该教程中的其他产品权限并非 WorkLite 飞书通道要求。

在应用的事件与回调配置中，分别将事件和卡片回调设为通过长连接接收：

- 事件：`im.message.receive_v1`。
- 回调：`card.action.trigger`。

开放平台保存长连接配置时可能要求应用客户端已经建立连接。可以先在 WorkLite 保存下述凭据，使连接客户端在线，再完成订阅设置和应用发布。卡片回调通过相同的 SDK EventDispatcher 处理，参考[官方 SDK 回调说明](https://github.com/larksuite/node-sdk/blob/main/docs/channel.zh.md)。

## WorkLite 配置

打开 WorkLite 的 **Chat → Channels**（`/chat?view=channels`），点击“扫码创建应用”，使用飞书扫码或打开确认链接，在平台确认应用和所属企业。服务端自动保存 App ID 和加密的 App Secret；返回了该应用下的 Open ID 时自动绑定用户并开始连接，无需复制凭证或再点击保存。没有返回 Open ID 时，页面保留凭证，只需补充该应用下的用户 Open ID 后保存。

等待状态持久化，网页刷新或 API 重启后可以继续；二维码过期后在可见页面自动更换。取消保留当前应用。已有应用的“扫码更换应用”会在确认完成后替换当前配置，因此开发和部署须分别使用自己的应用。拒绝或失败时可以再次发起，原凭证不被清空。

扫码注册类型、官方源码和 SDK 适配限制见[应用凭证自动化调查](credential-automation.md)。**凭证已保存不等于机器人已可用**：消息权限、事件、卡片回调、长连接接收方式和应用发布按上节完成，页面提供当前应用的开放平台入口，单独报告实际连接状态。PersonalAgent 与当前 SDK 的完整收发适配尚未经过真实联调。

已有企业应用仍可手动配置：

1. 在开放平台的应用凭据页面取得 App ID 与 App Secret。
2. 取得使用者在**这个应用下**的 `open_id`。它不是员工编号，也不能使用另一个应用的 open id。管理员可在官方 API 调试台使用[通过手机号或邮箱获取用户 ID](https://open.feishu.cn/document/server-docs/contact-v3/user/batch_get_id)，选择 open id 类型；查询所需通讯录权限不属于机器人消息运行权限。
3. 在页面的“已有应用”表单填写三个字段并保存。同一应用下留空 Secret 可保留已存凭据，更换 App ID 时必须填写对应 Secret。手动保存取消未完成的扫码尝试，迟到结果不会覆盖配置。

在 Chat 的 Configuration 中配置可用模型。Team 任务还需要配置 Team 角色；Workflow 必须拥有已发布版本。完成平台设置后，在飞书打开该机器人私聊并发送文字。

只接收配置的单个用户发来的私聊文字与卡片操作。目前没有群聊、语音、图片或附件输入。App Secret 仅通过配置页提交，不应放入聊天内容。

开发与部署须使用不同飞书应用。相同 App ID 的多个长连接客户端会分摊事件，不适合让两个 WorkLite 数据空间同时接收同一个应用。开发端口为 `3390`–`3392`，部署端口为 `23390`–`23392`；该通道不跨空间同步数据。

## 对话与任务

每条普通消息都进入 Chat 对话。总 Agent 自然回答问题，在任务意图明确时通过受保护的平台脚本分派到 Agent Team 或已发布 Workflow。只有当前请求存在需要用户决定的选择或缺少必要信息时，才出现相关问题与选项；点击选项回答当前问题后继续这次请求，也可以直接发送文字回答。回复不再附带“使用 xxx”菜单或后续消息模式，已保存的旧模式不再影响新消息。任务卡片仍可通过回复该卡片或提交表单补充信息。

Agent Team 继续使用现有 Coordinator intake 收集目标、项目目录与模式，保留一个活动 Run 的全局限制，其余请求排队。缺失信息可以通过任务卡片表单或回复该卡片补齐。命令授权必须在当前任务表单中逐行输入完整命令并提交，只有明确提交的精确字符串获得授权；普通聊天与模型脚本不产生授权。

Workflow 始终捕获最新已发布版本。卡片显示执行进度、待办二维码和可用的暂停、继续、取消或失败步骤重试操作；重试复用现有服务端 `retryable` 节点。

普通消息与等待回复卡片一同持久化，分派前先显示“已排队”，之后在同一张卡片中显示“正在思考…”、“正在回复…”或“正在处理…”。生成完成后仅保留回复正文，失败或取消保留已有正文和相应状态。对话回复按已持久化的增量文本通过 CardKit 原生打字机效果显示，使用快速上屏策略；状态与正文作为独立组件更新。工具执行、等待回答和本轮结束会关闭流式模式。状态文字配轻量原生图标，不依赖图标旋转或 GIF。Team 任务尝试与 Workflow 步骤执行状态显示在默认收起的“执行详情”面板内；当前步骤、结果、失败原因、问题、二维码和操作仍在面板外。每轮拥有独立边界。任务卡片跟随服务端状态更新。已接收事件和任务引用持久化，重复事件不会重复提交同一任务。卡片 ID、递增更新序号、上次成功显示的内容与未完成更新的幂等 UUID 和请求数据保存在既有任务提交记录中。断线恢复先以相同幂等 ID 重试未确认结果的更新，再推送较新的内容，不重新发送已确认的卡片。平台明确拒绝的更新会保留失败证据并结束该笔请求，后续使用新序号重新投递当前内容，以便恢复已过期的流式窗口。持续生成时自动续开平台的流式窗口。断线恢复后继续处理已接收消息和未完成投递；停机期间尚未接收的事件是否重放由飞书决定。

已提交的 Team 文档和 Workflow Artifacts 作为飞书原生文件消息交付。较长回复也发送完整文件。文件投递失败时，使用卡片上的“重试文件交付”，不会重新执行文档生产角色。Workflow Agent 的普通输出不自动创建 Artifact。

## 新版卡片生效

2026-10-06 起，新投递使用 CardKit 卡片实体。应用管理员需要在[飞书应用后台](https://open.feishu.cn/app)选择当前机器人应用，在“权限管理”中开通 `cardkit:card:write` 并发布权限变更；缺少权限时不会降级为旧整卡更新。已有旧方式发送的卡片不做实体转换，也不重发，未完成的旧卡片需要发送新请求。飞书客户端要求为 7.20 及以上，自定义流式速度从 7.23 起支持。2026-10-06 经用户授权执行 `pnpm deploy:local`，Gateway/Web 构建、API 编译和隔离启动预检通过，部署服务替换后 Web/API/Gateway 就绪。未运行测试或真实飞书卡片验收，权限发布与客户端效果仍需确认。

## 微信移除与生效

[能力更新与升级恢复](upgrades.md)说明总 Agent 的版本化扩展能力、轮次快照、独立升级执行器和飞书结果通知。项目升级需要先建立经过授权的托管运行基线；现有未托管服务不会被自动接管。

本次移除的是 **WeChat ClawBot 聊天通道**，包括旧登录与断开接口、轮询、连接凭据和对话映射；不提供旧接口别名或凭据转换。Codex CLI 执行插件与微信公众号 Workflow 发布能力继续独立存在。历史 Agent 执行记录保留。

新增数据库迁移 `0021_feishu_master_chat.sql` 删除旧 ClawBot 字段与映射表，并建立飞书会话、事件、任务提交和文件投递记录；`0022_chat_bot_capabilities.sql` 建立能力配置与轮次快照；`0023_feishu_registration.sql` 建立可恢复的应用注册状态。该迁移文件已写入仓库，实施过程中没有执行迁移，也没有启动、停止或重启 WorkLite 服务。下一次经授权使用新代码启动 API 时，既有启动迁移流程会应用它。

此次完成代码和文档修改，并按源码记录设计覆盖情况；没有运行测试、类型检查、构建或真实飞书联调。扫码确认和平台权限、订阅、发布仍需应用管理员完成；自动凭证获取尚未经过实际联调。
