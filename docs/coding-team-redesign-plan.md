# Coding Team 改造计划

## 目标和范围

将产品入口 Coding 更名为 Coding Team。用户通过现有 Chat 发起任务和发送控制指令；Coding Team 页面展示团队协作过程，本版本不在该页面提供聊天输入框。

新任务统一先交给 Router。Router 根据用户目标和角色能力决定调用哪些角色、哪些任务可以并行、需要等待哪些结果，以及接下来调用谁或何时结束。角色完成后向 Router 返回结果，由 Router 决定下一步；服务端不按角色数组顺序推断实施角色。部署等操作也由 Router 结合用户授权、角色能力和任务上下文安排。

团队页面以聊天形式展示真实消息及其发送者和接收者：Router 指派时显示 `@角色`，角色返回时显示 `@Router`。不虚构消息或交接关系，不额外增加用户未要求的展示字段。

用户可通过 Chat 指定某个角色停止当前工作；之后可要求该角色继续，由它根据已保存的任务和进度重新接手。暂不提供暂停功能。若一个角色有多个活动任务，必须消歧，不能默默选择或停止全部任务。

## 现状与问题

- 当前群组编排版本为 11，入口可落到 Dispatcher 或 Planner，现有 Dispatcher 只做一次模式决策；角色可以直接向其他角色交接，不能满足 Router 持续协调的要求。
- 现有执行中止控制以 Run 为单位，不能安全地等同于停止某个角色的任务。
- 执行快照中的多个角色都可能配置执行器，不能以第一个有执行器的角色作为实施角色。
- 群组消息已持久化发送者、接收者、Run 和任务尝试，可作为真实对话展示的基础。旧对话表仍有历史数据，清理前须迁移和核对。
- 工作区已有尚未完成的聊天展示及实施角色选择修改，实施时应审查和复用适用部分，避免把它们误认为完整实现；同时保留其他未提交工作。
- 最新实施要求改为彻底删除废弃的 pre-group 对话数据，不建立归档副本，也不保留兼容读取路径。

## 设计与实施

### 1. Router 编排

1. 明确 Router 的稳定角色 ID、默认配置和可用工具，并为现有 Coding Team 配置提供迁移；不覆盖用户对其他角色的配置。只执行 Router 编排版本，移除 v1–v11 Run 的运行、恢复和历史读取兼容；迁移删除这些旧 Run 及仅用于旧 Run 的记录，同时保留 Coder 当前配置和 Router Run。
2. Chat 发起的新任务只进入 Router。Router 可以直接回答、向一个或多个已配置角色分配具体任务，或等待用户提供必要信息。服务端验证角色、任务目标和仓库范围，不允许模型选择未配置角色或扩大授权范围。
3. 将角色调用、目标、依赖、状态和结果持久化。每个角色结果返回 Router；Router 根据已经完成和仍在运行的任务选择等待、追加调用、重新分配或结束。并行任务独立记录，避免一个失败或停止导致其他任务的结果丢失。
4. Router 每次恢复都能获取原始目标、相关消息和所等待任务的结果；使用稳定任务标识和幂等写入，支持服务重启、重复事件和恢复，避免重复派发。设置有界循环及明确的失败处理，避免无进展的无限调度。
5. 替换旧提示词中角色直接交接和固定模式流转的要求；更新 Chat 的产品能力说明，确保配置、协议和实际行为一致。

### 2. 角色停止与继续

1. 将控制范围精确到运行中的任务实例，而不是整个 Run。引入任务级取消信号并向实际执行引擎传播；确保并行任务只中止被指定实例，保留已经产生的消息、文件和进度。
2. 记录请求、执行结果和终态；处理已完成、正在停止、进程已退出、停止失败及服务重启等情况。Router 收到状态变化后继续协调，不把停止当作成功完成。
3. 继续操作创建关联原任务的新尝试，带上可恢复的目标、上下文和已保存进度，不声称能恢复进程内状态。明确先前结果和新尝试的关联，避免覆盖历史。
4. Chat 控制必须绑定正确的团队运行与角色任务；同角色多任务时请求用户指定目标。控制指令幂等，权限和仓库范围沿用原任务。

### 3. 对话页面

1. 重做 Coding Team 的运行详情，按持久化顺序展示用户、Router 和角色的真实消息及真实 `@` 对象。增量更新时去重，断线后从持久化记录恢复。
2. 支持多个角色并行回复，展示必要的任务状态及停止后的实际结果。问题和控制继续由 Chat 处理，不在 Coding Team 页面添加输入框。
3. 没有对应持久化消息的运行不通过旧详情页或归档路径兜底，不伪造 Router 消息。v1–v11 Run 和仅属于这些 Run 的历史证据由迁移删除；不恢复旧图执行。

### 4. 废弃代码与数据表

1. 逐项梳理旧编排、路由、提示词、API、前端组件、契约和表的引用。删除不再使用的兼容代码和类型；不为废弃的 pre-group 数据提供读取回退。
2. 移除旧 `coder_conversations`、`coder_intakes`、`coder_conversation_messages`、`coder_conversation_events` 中的全部数据及表定义，不复制到归档表，不保留兼容读取 API 或工具。
3. 编写版本化迁移，在空库和已有数据库路径中删除上述废弃表；迁移后核对旧表与归档路径均不存在，并验证外键完整性。

## 验收与验证

- Chat 发起任务后，首个接收角色始终是 Router；Router 可直接答复、串行调用或并行调用角色，角色结果返回 Router 并驱动下一步。
- 即使 Planner 和 Implementer 都配置执行器，也不会根据数组顺序误派；部署只按用户授权和 Router 的明确分配执行。
- 页面按真实顺序展示消息和 `@`，并行角色完成顺序可不同；刷新、断线重连及服务重启后不重复或丢失消息。页面没有输入框。
- 从 Chat 精确停止一个角色任务，不影响同 Run 的其他任务；继续产生关联的新尝试并使用已保存上下文。多个同角色任务必须先消歧。
- 覆盖执行失败、停止竞态、重复控制、角色不存在、越权仓库、Router 重复派发、等待用户、服务重启，以及迁移对 v1–v11 Run 和关联历史的删除、对 v12 Router Run 与当前 Coder 配置的保留。
- 用含旧对话记录及空数据库测试迁移：验证废弃表数据被删除、旧表与归档接口不存在、外键完整，并确认新群组结构仍可初始化。
- 运行相关调度、控制、迁移和页面测试，以及受影响包的类型检查；报告实际验证结果和未验证项。
